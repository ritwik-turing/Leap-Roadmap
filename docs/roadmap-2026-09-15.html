Roadmap: where we have been, what is next

Ten sprints since 20 April. Evaluation moved to the centre of the product on 24 August and is now the spine everything else attaches to. Six things are in store after it, in the order below.

The one line. Evaluate is close to done as a product. The next six months are about attaching the rest of the lifecycle to it: certification, observability, the tenant side, the marketplace, and where the agent code comes from.

What is in store, in order

0 · finish firstnow

Evaluations, hardened

Close the 14 Sep list so Evaluate is the stable spine the rest attaches to.

Stands
Summary and comparison views broken, trace view in the wrong layout.
Done when
Summary, compare and span-timeline traces work on the seeded demo. Per-metric versioning and the playground in the backlog with owners. Names match across products.
Gate
Custom code execution in metrics: security and architecture call, due diligence with Youanka.
1 · certificationnext

Certification and the verifier persona

Submit for verification writes a record. Someone has to pick it up, review the evidence, and certify or send it back.

Stands
Verification tab and the console queue exist as shells. Certification is a stub pending Guardian.
Done when
A verifier opens the queue, sees the evaluation evidence at the exact versions, decides, and the decision shows on the agent and in the marketplace badge.
Gate
The persona question. Yasir overruled a separate verifier model on 11 Aug; it needs re-settling now that submit-for-verification is real.
2 · observabilitynext

Observability metrics

Latency, tokens, cost and error rate per agent version, fed by the same traces evaluation already produces.

Stands
Observability tab is a shell. Product spec written. RC-5 observability slid a full sprint in S9.
Done when
The tab shows real numbers from evaluation runs and sandbox traffic, and a version-to-version delta.
Gate
Trace view reformat lands first, so the span data model is shared.
3 · tenant sidenext

Tenant admin flow

Wire Tenant Admin Console V4 to the lifecycle: verification queue, policy, member access, records.

Stands
Console V4 is a standalone prototype. Multi-tenancy itself is HUMAIN's at platform level since 11 Aug.
Done when
A tenant admin sets policy and access, sees every agent's verification state, and the console consumes HUMAIN's tenant model rather than our own.
Gate
HUMAIN's tenant and identity contract.
4 · marketplacenext

Marketplace integration

Publish from the lifecycle into the marketplace listing, carrying the verification record and badge a buyer sees.

Stands
Public Marketplace V16, cut to the tenant acquisition flow. Publish path exists in the LEAP demo.
Done when
Certified agent publishes to a listing, buyer acquires through the tenant flow, and the badge links back to the evidence.
Gate
Monetisation, payment and checkout stay out for LEAP, by decision.
5 · agent creationdecision

Agent creation, HUMAIN code integration

The agent YAML that starts the whole loop: prompt-generate an agent, evaluate it, iterate, certify, publish.

Stands
Submit Agent step 1 is a manifest upload. YAML holds model, prompts, hyperparameters, tools. Whitelisted HUMAIN developers author the first files.
Done when
HUMAIN's code-gen output lands in Submit Agent without hand editing, and an eval run follows in one flow.
Gate
Scope conflict. Sandip and the team say code generation is in Turing's scope; Sijong said it is HUMAIN's. Unresolved since 24 Aug.

Three of the six are blocked on a decision rather than on build time: the verifier persona, HUMAIN's tenant contract, and who owns agent code generation. Those are the ones worth your minute.
